# Chronux

基于事件**时序驱动模型**的**声明式**、**轻量级**动画渲染引擎。

建议首先阅读 [Chronux DSL 语法介绍](docs/dsl.md)，快速了解 Chronux 的核心设计理念。

[作品集](https://space.bilibili.com/31771737)

## 环境要求

* Rust 版本（MSRV）：1.97+
* 系统依赖：FFmpeg
* 需要平台支持的第三方库：Skia、Harfbuzz（自动链接）

## 使用方法

### 命令行参数

```
Usage: chronux [OPTIONS] --output <OUTPUT>

Options:
  -i, --config <CONFIG>    动画配置输入。可以指定多个，按照出现在参数中的顺序拼接。
  -o, --output <OUTPUT>    输出文件名。如果渲染到 PNG 序列（--encoder pngseq）则为 PNG 序列对应的目录名。
  -w, --encoder <ENCODER>  指定输出方式。默认值为 PNG 序列（pngseq），也可以选择 ffmpeg（视频）、timeline（输出每个动画事件对应的时间，CSV 格式）, objects（仅输出对象列表）。
```

### Chronux DSL 语法

Chronux 是一个**声明式**动画引擎：动画制作者需要**声明**每个事件（动画）的名称、种类、参数和时序关系，而不需要关心时间轴的操作——这将由 Chronux 自动处理。

核心语法说明参见 [docs/dsl.md](docs/dsl.md)。

## Chronux 的特点

1. **直观的事件模型**：基本概念与 PPT 动画类似，非常容易理解；
2. **按照任意顺序书写事件**：Chronux 会自动按时间顺序排序；
3. **可以随意在视频的中间插入或者删除动画，而不需要调整整个时间轴**：只需要处理好与这些修改前后衔接的事件即可；
4. **工程化能力**：动画声明文件可以任意拆分，允许用户分场景/分类型/按时间顺序/总之按照任何方便的方式组织复杂工程；
5. **极致性能**：时长 30 分钟、规格为 4k@60fps 的视频仅需 50 分钟即可渲染完成；其他使用 After Effects 制作的同类同规模动画在相同的规格下可能会内存溢出，即使勉强运行或者降低规格到 1080p@60fps，也需要 10 小时以上的渲染时间；
6. **适配 AI 时代的生产力**：动画 DSL 基于纯文本的 TOML 语法，可以结合任意一种喜欢的现代 AI Coding 工具快速书写，也可以做成 Agent Skill 以便从更高层次掌握工作；
7. **优秀的扩展性**：Chronux 的核心理念——基于时序关系的事件驱动模型以及使用镜头的输出模式——可以很容易扩展到更复杂的 3D 特效。
